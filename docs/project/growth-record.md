# 成长档案

协议目标为 Contracts 的 `growth-record-v1-r1`，摘要 `11e1160054010b313a5339d25a5bf25fa8749bddada5491184ccdb7f21eb3ecd`，入口见 [交接](../../../contracts/.validation/growth-record-v1-handoff.md)与[业务边界](../../../contracts/docs/coordination/growth-record.md)。这份本地目标不代表 Provider 已部署或完成端侧验收。

## 入口与读取

“我的”资料页提供成长档案，首页“党员成长档案”和“政治生日”进入同一原生列表，后者预选类型。本人列表使用当前 Person 的历史集合；组织/他人范围从已获准记录进入，不查询公开 User→Person 绑定。列表遵守服务端不透明游标、发布时间顺序和 postId 去重；有标题时以标题识别记录，无标题时直接展示正文或媒体，不使用记录类型补占位标题。筛选、账号、绑定变化清空旧集合及游标，隐藏页面清空私有展示，回到前台重新读取绑定和业务权限。

详情使用 GrowthRecord/GrowthLifecycle，并将 PRIVATE、管理隐藏、临时组织可见、安全检查状态分别说明。原发布账号与稳定 Person 不互相替代，编辑、删除、评论及其他动作只由 availableActions 展示；写入时服务端仍最终判权。评论、通知 commentId 定位与举报复用原组件，成长通知标志只进入成长详情，不回退普通公开 Post。分享只给不含内容和组织信息的通用首页。

## 发布、编辑与恢复

发布组织和类型来自当前发布选项；只有一个可用组织时自动预选，列表的记录类型筛选会作为新建预选，存在多个组织时仍由用户明确选择。已选媒体时先移除才能切换上下文。政治生日是主动分享，不维护日期、提醒、周年或自动记录，相关说明只在选中该类型时展示。编辑读取 getPost(view=edit) 的 GrowthRecordEditable 与强 ETag，以 If-Match 提交，不改 Person、组织、类型或发布时间。

图片与 MP4 使用成长专属分配、不可覆盖上传和登记，只提交 mediaId，不把普通附件、学习成果或积分材料导入。分片视频复用 User 子包内的安全上传实现；上传成功不表示技术或内容检查通过。登记响应不确定时重用 uploadId/fileIndex；传输结果不确定则重新分配对象，不覆盖、不据冲突推断成功，也不由客户端删除对象。

创建提交结果不确定时锁定原正文和媒体引用，保留原 Idempotency-Key 与精确请求体，允许显式恢复。同一登录会话内退出页面后可继续恢复；账号或绑定变化使旧操作失效。正文与上传凭证只在内存，不写 Storage，进程退出后不承诺恢复草稿。编辑冲突或未知结果保留草稿，重新读取并核对当前版本后才能继续提交，不能自动覆盖。

## 受控媒体

媒体详情不把受控 URL 直接交给 image/video。用户打开时重新读取绑定和成长详情，再以当前认证下载同源受控字节；完成后再检查当前身份。图片通过本地临时文件预览，视频完整下载后本地播放，不请求公共 COS、签名跳转或匿名播放地址。下载任务随页面失效中止，迟到结果清理；本地文件在离开、换绑或下次读取时清理。原生图片预览期间保留正在查看的临时文件，返回页面时清理。临时组织可见到期重新读取并停止本地媒体展示。

Node 回归和静态检查不能证明实际微信的认证下载、重定向处理、200MiB 文件限制、视频编码/播放、平台域名或 Provider 的逐 GET/HEAD/Range 授权。当前完整下载路径不产生远程视频 Range 播放；服务端 Range、真实 COS/检查能力、微信编译与真机仍需在已验收目标环境验证。普通 Post/QA 媒体边界不扩张；接入服务必须先具备 Contracts 要求的全入口组织隔离和必要视频检查能力。
