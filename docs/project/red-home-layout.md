# 栏目首页与校园辅助页

小程序默认首页为 `pages/index/index`，以党建内容、学习入口和活动为主。校园动态、提醒、发布能力保留在校园辅助页。

- 底部导航顺序：首页、校园、消息、我的；消息角标索引为 2。
- `pages/campus/campus` 通过校园 Tab 访问，仅校园页预加载 Community。
- 原 `subpkg_red/pages/index/index` 作为既有分享兼容入口切换到首页。
- 六型分类、31 个栏目及已有子项名称保留在[党建栏目名称清单](party-columns.md)，不接入运行时代码。首页移除目录、介绍、展开交互及专属样式。
- 首页移除“品牌与校园服务”链接区。官方内容页面保留供 E·安全历史入口使用；公共事项和校园页保留原有其他入口。

## 首页 UI/UX V1

首页结构依次为品牌与重点内容轮播、八项常用导航、党建资讯和近期活动。静态导航不依赖动态请求成功。

- 数据边界位于主包 `pages/index/home-data.ts`，展示映射位于 `home-model.ts`。首页以 [首页摘要](../../../contracts/api/paths/home.yaml) 为动态内容来源，按返回顺序展示精选、党建资讯和近期活动。精选、资讯和活动卡片进入既有 Article / Activity 详情，校园页独立读取公共事项提醒。
- 首屏使用轮播和列表骨架。各模块独立处理 `READY`、`EMPTY`、`UNAVAILABLE`。不可用模块清除旧卡片并提供重试入口，整体请求失败清除整个动态摘要，静态导航继续可用。封面失败使用占位。
- 下拉刷新、模块重试与整体重试都重新读取首页摘要。重复刷新共用加载门禁，账号切换时清除旧摘要，请求代次和卸载保护阻止旧响应写回。
- 下拉刷新成功、部分失败和失败均有反馈；后台返回首页按 60 秒客户端 freshness 策略决定是否刷新，该策略不是 HTTP 缓存或服务端时效保证。
- 开发版可在开发者工具编译模式为首页设置启动参数 `preview=empty`、`preview=partial` 或 `preview=error`，分别检查空数据、部分失败和整体失败。模拟集中在 `home-preview.ts`，只返回空结果或错误，不生成虚假内容 ID / 详情操作；体验版和正式版忽略该参数。正常内容与真实接口错误不在此模拟范围内。

证据范围：源码、配置及 Node 模拟/静态回归。页面几何、轮播、下拉手势、图片加载、分包跳转、真实账号 HTTP、安全区和不同屏幕仍须微信开发者工具或真机核验。

回归命令：`node scripts/test-red-home.mjs` 检查首屏路由、目录与服务链接移除、摘要请求、模块状态、失败清除、重试、旧响应隔离、开发态模拟、旧分享入口及消息角标归属；`node scripts/test-home-public-matter-reminders.mjs` 检查校园提醒。
