# 通知偏好与渠道

协议以 [通知交付协调](../../../contracts/docs/coordination/notification-delivery.md)及 canonical [OpenAPI](../../../contracts/api/openapi.yaml) 为准。消息消费与阅读归 [消息中心](notification-center.md)；本页仅维护设置区域与原生订阅交互。

## 归属与交互

[设置 Action](../../subpkg_setting/actions/notification-preferences.ts) 持有本人登录期内存快照，登录/退出使旧请求失效；[Service](../../subpkg_setting/services/notification-preferences.ts) 验证首版九类别×三渠道偏好及33类型×三渠道能力的完整已知集合，不补造缺项，不回退旧设置。未知扩展组合不显示、不回写。模块保留在 Settings 分包。

设置页按活动提醒、事项提醒、评论、回复、点赞、审核与处理结果、系统消息、学习任务、积分结果分别展示“站内消息”“微信提醒”。服务号入口隐藏，其协议组合仍校验但不更改。评论、回复、点赞保持独立。开关只保存接收意愿，保存成功反馈“已保存”；模板或渠道暂不可用也允许保存意愿。失败保留已有有效表示，显式重试；无快照不显示全部关闭。关闭站内消息不清历史、不改已读、不补发。

## 微信订阅

主要入口为发布普通帖子/导师提问、可被回复的评论/正式回答、关注活动/公共事项、新平台报名、需审核的学习成果和积分申请。[共享业务订阅](../../services/business-subscriptions.ts) 通过已有本人目录 API 提前加载 sceneCode 和必要 resourceId，Backend 按场景与当前业务状态选择模板；小程序不按标题、ID或通知类型推导场景。页面完成同步校验后在用户点击中直接请求微信；学习成果在原确认框的明确确认回调中请求。缺目录、过期或偏好未知时跳过申请；原生拒绝/异常不阻断业务，不以订阅成功替代业务成功。修改已有帖子、核实未知操作、无需审核的学习确认不重复申请。

类别关闭时不请求、不自动开启。共享审核模板分别使用学习/积分类别，授权不污染其他偏好。每次操作最多一次请求，取服务端上限3和本机兼容上限的较小值；模板ID、标题、种类去重与组合限制沿用[共享规则](../../services/notification-subscriptions.ts)。不自动连续弹窗，不上报授权、不维护次数。近期拒绝按登录期内模板抑制5分钟，记住的拒绝和微信总开关关闭时跳过；在设置中提供主动恢复入口。

设置页仅保存类别意愿，移除逐模板申请按钮和目录清单；保存后的网络回调不弹授权。`wx.getSetting({withSubscriptions:true})` 只作本机引导，读取失败保持未知；`wx.openSetting` 仅由用户点击触发。账号变化、偏好更新、页面卸载使准备的快照失效；业务上下文变化独立复核。原生弹窗造成的临时隐藏不应丢失正在提交的学习操作。

## 验证边界

[设置回归](../../scripts/test-setting-subscription.mjs) 使用模拟微信和本人API验证协议完整性、独立保存、分组、结果与异步失效；不能证明微信弹窗、域名、Provider发送或设备收件。真实微信投递仍由Backend/Provider与真机联调确认，不将客户端静态或模拟检查当作投递证据。
